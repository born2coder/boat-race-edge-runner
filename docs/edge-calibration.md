# 確率・確定オッズ補正 v1

## 目的と適用範囲

HIT/EDGEの元モデル・学習済み重み・特徴量・順位を変更しない。
展示後の全120通りの出力を入力として、①確率の校正と②確定オッズの
見積もりを別々に検証する。現行購入台帳の判定も変更しない。

まず `shadow`（比較検証）運転。検証通過でも自動採用せず、
前向き記録の検証後、別のルールバージョンとして接続する。
精度や利益の改善を保証するものではない。

## 自動実行・保存

既存 `watch_research_forward.py` の日付初期化時に、ローカルに同期済みの
直近60日を読み、1日1回学習・検証。学習のための外部通信はない。

- `state/edge_v2/calibration/YYYY-MM-DD.json`：固定された日次補正と検証
- `state/edge_v2/calibration/latest.json`：画面が読む最新レポート
- 日次race内 `final`：全120通りの確定オッズと取得時刻・出所ハッシュ
- 日次race内 `calibration_shadow[snapshot_id]`：補正確率、平均／下位25％点の
  確定オッズ見積もり、補正期待値、補正バージョン

既存DataPublisherが `edge-data` ブランチへ保存するため、観測更新による
アプリ再デプロイは発生しない。Supabaseのテーブル追加・書込増はない。
Supabaseの既存台帳 `finalOdds` はこの変更では埋めない。新しい全件証跡の
正本は上記の日次ファイルとし、検証画面はそこから作成した集計を読む。

## 確定オッズの収集

結果精算8リクエスト枠の余りで、最大2レースずつ収集。
結果精算が8件ある回は0件。1レース最大3回、15分以上間隔を空ける。
現日・前日の既に記録されたレースのみ。過去全日へのネットワーク走査はしない。
既存の実行時間・送信頻度・利用上限は維持する。

公式ページの日付・場・レース番号を照合し、全120通りが有効であること、
締切後の取得であること、的中組の倍率×100が確定払戻と一致することを確認する。
返還・中止は校正対象から除外する。欠測は推定値で埋めない。
一時失敗は欠測として保持し、401/403/429は安全停止を維持する。

## 学習と評価

送信ACK済みで、締切前に公開された全120通りの観測のみ。
買い目として選択されなかった組合せも含む。レース×観測フェーズを重複排除し、
同一モデルハッシュに限定する。朝と展示後を混ぜない。
結果の確認時刻・確定オッズ取得時刻が集計日0時以降の情報は使用しない。
後日確認した結果を過去時点の学習に戻して使用しない。

- 時刻別：20/15/10/5分前。実際の取得時間帯は従来のphase定義に従う。
- 時系列分割：最新3観測日を検証、それより前を学習。同じレースは跨がない。
- 確率：固定候補のtemperature scaling。順位は保持し、120通りの総和は1。
  学習期間の対数損失で係数を決め、検証期間の対数損失・Brier・確率帯別実測率を表示。
- オッズ：時刻×判定時オッズ帯（10/30/100/300倍の境界）別に、確定/判定の倍率比を集計。
  平均比を点推定、下位25％点を控えめな見積もりとする。信頼区間・保証値ではない。
  同じレース内の120通りを独立した120レースとは数えない。
- 比較：同じ対応済み買い目の集合で、既存の `p×0.8×観測オッズ` と
  `校正p×控えめな確定オッズ` を、固定120％基準・1点100円で比較。
  本番台帳の結果ではなく、各フェーズで独立した事後検証。フェーズ間合算は禁止。

必要条件：学習7日以上／検証3日以上、各100レース以上。
オッズ帯にも学習100レースを要求し、不足する帯の期待値はnull（買い判断なし）。
確率は対数損失改善かつBrier非悪化、オッズは平均対数誤差改善かつ
控えめな見積もりを下回る割合35％以下を検証条件とする。
これらは初期の工学的な判定基準であり、統計的な有意性や収益性の証明ではない。

同じ検証期間を繰り返し見るだけで採用しない。変更案を固定し、その後の
前向きshadow記録で検証する。前向き記録には使用補正バージョンを残す。

## 画面と停止時

運用成績のリンクから `/calibration` へ。
不足／未達成／導入判断待ち、学習・検証件数、確率の誤差、オッズの誤差、
同条件の回収率を表示。古いレポートは更新日を明示する。
取得失敗は合格やゼロ件とみなさない。既存所有者認証を維持する。

補正計算・注釈失敗は `calibration_status` に記録し、元の収集を止めない。
日次補正は同日の再起動で再学習しない。モデルハッシュ不一致・古い日付は使用しない。

## v2：2026-10-26に固定した比較戦略

実験ID `calibration-strategy-20261026-v1`。本番購入台帳・HITモデル・取得上限は変更しない。

- 確率は全120通りの学習期間の実績から固定7帯で校正。200件分の元確率への平滑化、単調回帰、線形補間、レース内正規化を行い、順位と総和1を維持する。検証期間の結果で係数を選ばない。
- 3方式：元p×0.8×観測オッズ、補正p×観測オッズ、補正p×控えめな確定オッズ。すべて元p>=1%、期待値>=1.2、1点100円。現行「購入推奨」の計算を固定時刻で再現した比較で、本番台帳の累積購入成績とは別。
- 同じ評価可能な集合で比較。確率・確定オッズの学習7日以上、100レース以上を満たさないものは未評価。推測値による埋め合わせはしない。
- 全件／判定時20倍未満の2枠。20倍ちょうどは限定枠に含めない。
- 時刻比較は15/10/5分前すべてがある同一レース、同一組合せの評価可能集合。購入条件を満たす組合せは時刻で変わる。20倍未満枠の集合も時刻で変わる。20分前は通常の時刻別表示のみ。
- 日別収支、日末ベース最大ドローダウン、払戻上位5点への依存率を表示。日中の最大損失を表す指標ではない。
- `calibration_shadow` に実験ID・3方式の判断配列を締切前に保存。前向き集計は記録時刻<=公開受領時刻<締切、ACK済み、同モデル、新実験IDの記録だけを採点。後から再計算した判断は混ぜない。直近60日の確定分が対象。
- 日次ファイルは `calibration/edge-calibration-v2/YYYY-MM-DD.json` に固定保存し、v1を上書きしない。`calibration/latest.json` が画面の参照先。画面は旧v1も読めるが、新方式の結果に見せない。
- 過去の試算・ルール固定後の成績は分離。検証通過しても自動採用しない。今後ルールを変える場合は実験IDも変更する。

検証：`python -m unittest tests.test_calibration_strategy tests.test_edge_calibration`、`cd web && npm run build`。

## v3：確率補正と0.8係数の分離（2026-10-31）

新実験ID `calibration-factorial-20261031-v1`。従来の3方式と実験IDは継続する。
同じ観測オッズに対し、A＝元確率×0.8、B＝元確率×1.0、C＝補正確率×0.8、D＝補正確率×1.0を比較する。
元確率1％以上、期待値1.2以上、1点100円が共通条件。各時刻の全件／観測オッズ20倍未満を別々に採点する。
確率補正の比較はA→CとB→D、係数を外す比較はA→BとC→D。
回収率差はパーセントポイントで表示し、購入点数・収支の差も表示する。統計的な因果効果や有意差を保証しない。

確率校正の学習7日・100レース以上を共通の評価条件とする。確定オッズの推定を使わないため、
確定オッズ表やその学習件数の不足を理由に4方式だけを除外しない。精算は公式の確定払戻で行う。
レース内120通りを120レースとは数えず、フェーズ間や全件／20倍未満を合算しない。

日次レポートは `calibration/edge-calibration-v3/YYYY-MM-DD.json` に固定保存し、v1/v2を上書きしない。
`phases.*.factorialComparison` は時系列分割された検証期間の過去試算。
`factorialForwardComparison` は締切前に保存した新実験の判断だけを採点する。
新規の `calibration_shadow` に `factorialExperimentId` と `factorialDecisions` の4配列を保存する。
記録時刻<=公開受領時刻<締切、ACK済み、同モデルという既存の検証を通す。
旧3方式の判断から前向き4方式を再構築せず、旧実験ID・遅い記録・欠損配列・方式ごとに異なる評価可能集合を除外する。
旧レポート表示中は4方式の集計待ちと明記する。

本番購入判定・モデル・DB書込・送信間隔・外部取得数・実行時間上限は変更しない。
次の通常起動で新形式の日次レポートと将来の判断記録が作られる。過去の予測・判断は後付けしない。
