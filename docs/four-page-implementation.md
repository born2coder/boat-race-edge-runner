## 実装と停止状態

既存のNext.js構成を維持し、4ページ、保存済みデータの読み取り、共通判定・仮想購入・精算・集計、設定下書き、追加型の移行を実装した。画面だけのモックではなく、保存データ用のサーバー実装とSQLを含む。

本番公開、GitHubへのpush、PR作成、本番API・DBへの接続、移行の本番適用、収集・監視・Actionsの再開は行っていない。既存の未コミット変更は別作業ツリーに残したまま保全した。既存の予想モデル・初回BUY・結果・払戻・観測履歴を削除／再分類して書き換える処理は追加していない。

## データ対応・確率の根拠

| 表示・記録 | 保存済みデータとの対応・計算 |
|---|---|
| 推定確率 | 既存`edge-full120-v2`の保存済み展示後スナップショットの120通り確率。新しい推論を閲覧時に実行しない |
| 補正確率 | 未導入。新ルールではnull／「—」。モデル値をコピーしない。旧記録に値がある場合はその記録値を保全 |
| 保守確率 | 既存の暫定係数0.8×推定確率。統計的下限ではないことを各ページと詳細に表示。未確認の係数で欠損を補完しない |
| 期待回収率 | 保守確率×その観測時点のオッズ。内部は倍率、画面は％。十進表現に基づく積で100％・120％の浮動小数境界の誤判定を抑制 |
| オッズ | 保存済みスナップショットの同一組み合わせのオッズと観測時刻。履歴では初回購入記録値を固定。記録時／最終取得／確定を区別し、未取得は「—」 |
| 締切 | 保存済みレースの公式対応が検証された締切。未検証なら通常候補へ出さない。発走予定を締切の代わりに埋めない |
| 終了／残り | 保存済み結果で終了確認。中止は別計上。締切済み・結果待ちは確認中。データ不足はnull／「—」 |
| 払戻 | 公式確定の100円当たり払戻。記録時オッズで精算しない |
| 旧初回BUY | `research_signals`のbuy_at／buy_odds／buy_ev／確定払戻等。対応する初回観測がある場合のみ元確率を復元。ない値はnull。保守確率のみ元buy_ev÷buy_oddsにより読み取り表示できる場合がある |
| 履歴イベント | 新ルールは保存済み120通りの判定観測、旧ルールは既存イベント。初回掲載・昇格・解除・締切・精算は保存された根拠を表示。仮想購入時刻と初回掲載を区別 |

保存時刻、オッズ取得時刻、予想生成時刻、画面表示時刻を分ける。最終画面更新を元データの鮮度として扱わない。

## 共通判定・記録・精算

- 新しい判定ルール版は`four-page-v1`。モデル版は既存`edge-full120-v2`。旧raw EV1.5、WATCH1.05、最大3点は新表示の隠れた条件にしない。
- 推定確率1％以上、残り時間0秒超〜1,200秒以下、公式締切・識別・確率・オッズ・300秒の鮮度等を検証する。100％ちょうどは除外、100％超〜120％未満は任意候補、120％以上は推奨。判定前に表示値へ丸めない。
- 欠損、古い観測、中止、結果判明、停止等は理由付きで除外する。全120通りの保存と除外理由を共通保存契約に含める。
- 「推奨のみ」「任意のみ」「両方」は独立した運用。各方式で最初の条件到達時に1点100円。「両方」は前二つの合算ではない。
- ルール版・モデル版・方式・実績種類・レース・組み合わせで重複排除する。初回値は不変。再試行、昇降格、再表示で増額しない。
- 新規記録はサーバーの実際の保存判定時刻を使用する。遅れて到着した古い観測や結果後の観測から過去の購入を作らない。承認日時以前、および承認時点ですでに表示窓へ入っていたレースは新版の記録対象外にして途中混在を防ぐ。
- 公式払戻による確定分だけで主回収率の分子・分母をそろえる。結果待ち・確認中は未確定投入として別表示。返還は元購入額と返還額を履歴に残し、主回収率の分子・分母双方から除外する。
- 未対応の同着等、確定時刻・結果・払戻の欠損は確認中。確定済みの再精算では書き換えない。
- 最大連続不的中は全対象点が確定・不的中のレース単位。最大資金減少は0円を起点に同時刻の精算をまとめる。グラフ終点と主収支は同じ共通集計から生成する。
- 確率・期待回収率の帯は下限含む／上限含まない。残り時間は15分超〜20分以下、10分超〜15分以下、5分以上〜10分以下、0分超〜5分未満。過去の記録値で分類する。

旧版は元の初回BUYだけを読み取り変換して推奨方式へ表示する。旧データに必要な事前観測がない任意／両方の成績は算出不可。新基準で過去を埋めない。「過去データ試算」「実購入」は種類を分離し、実購入は未導入として無効表示する。既存の過去試算は旧研究画面に残す。

## 利用量・認証・設定保存

読み取り処理から書き込み・外部取得・予想再計算・ジョブ開始を呼ばない。締切と鮮度の失効はページ全体の端末内タイマーで処理する。停止時はタイマーもオフ、非表示タブでは更新を抑制する。APIポーリングやカードごとの定期通信は追加していない。

保存済みの小さな購入記録をサーバー側で期間・版・方式・会場まで絞り、60秒の共通キャッシュを使う。履歴はレース単位のページ分割とそのページの詳細だけをブラウザへ返す。生の120通り全履歴をブラウザに送らない。1,000件ずつ最大50,000件まで読み、超える場合は期間を絞るよう明示する。無言で集計を切り捨てない。読み取りのタイムアウトは8秒、無限再試行なし。

設定保存は既存所有者セッションをサーバーで検証し、値・単位・刻み・下限と上限・将来日時を検証する。保存時は独立した下書きテーブルだけに書き、稼働条件は変更しない。同じ送信の再試行は同じIDになり、重複版を作らない。失敗時は成功表示を消す。係数、鮮度、100円は今回固定で研究条件を勝手に変更しない。

新しい記録入口`recordObservation`、精算入口`settleRecordedRace`と原子的RPCは実装したが、停止中の既存収集ジョブ・APIに接続していない。記録入口には環境変数とDBの承認日時／記録許可の二重ゲートがある。移行直後の記録許可はfalseで、下書きを保存しても変わらない。

## 開発環境での再現

本番資格情報を持たない開発環境を使う。Nodeは22.13以上。`web`で`npm ci`、`npm run build -- --webpack`、`node --test tests/*.test.mjs`を実行する。`.env`や本番秘密情報をテストへ渡さない。ビルド時の外部要求拒否には`tests/four-page/network-guard.cjs`をNodeの`--require`で利用できる。

SQLと画面検証の追加依存は製品package.jsonへ追加していない。別のテスト用ディレクトリに`@electric-sql/pglite@0.5.8`、`playwright@1.62.1`、`@sparticuz/chromium@153.0.0`を入れる。

`FOUR_PAGE_PGLITE_MODULE`をPGliteの`dist/index.js`の絶対パスにして、`node tests/four-page/migration-check.mjs`を実行する。

画面検証はLinuxのローカルループバックを使用する。`FOUR_PAGE_PLAYWRIGHT_MODULE`をPlaywrightの`index.js`、`FOUR_PAGE_CHROMIUM_MODULE`をChromiumの`build/index.js`、`FOUR_PAGE_CJK_FONT`を日本語フォント、`FOUR_PAGE_TEST_OUTPUT`をテスト出力専用ディレクトリに指定して`node tests/four-page/browser-check.mjs`を実行する。ポート4998／4999を使用する。出力先の`fixture.json.drafts`は毎回初期化されるので、研究データを置く場所を指定しない。ハーネスはテスト用所有者認証を注入するため、公開ネットワークへ公開しない。
